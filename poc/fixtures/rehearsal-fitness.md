# שיחה מדומה: מאמנת כושר (מתאים לקטלוג `catalog/fitness-mock.json`)

שיחת אבחון של 8–10 דקות. אחד מכם הוא היועץ, והשני "הלקוחה". אין צורך להקריא תסריט, מספיק שהלקוחה תכיר את הרקע ותענה בחופשיות.

## הרקע של הלקוחה (דנה)
- מאמנת כושר אישית, כ-45 מתאמנות פעילות.
- לידים חדשים מגיעים כמעט רק מאינסטגרם, בערך 20 בחודש.
- תפריטים נשלחים כקבצי PDF ומעודכנים ידנית, וקשה לה לעקוב מה כל מתאמנת אוכלת.
- מעקב אימוני אירובי נעשה בהודעות וואטסאפ, ואחר כך היא מעתיקה לטבלה.
- שאלונים נשלחים בטפסי גוגל, ואין לה מעקב תקופתי מסודר, והיא שוכחת לחזור למתאמנות.
- היא רוצה יותר מתאמנות דרך המלצות, למשל הטבה למי שמביאה חברה.
- היא חושבת על מכירת תוספי תזונה, אבל זה פחות דחוף.
- **מספר שהיא צריכה להגיד:** "אם נרשמות עוד חמש מתאמנות בחודש, זה בערך 3,000 שקל".

## מה היועץ שואל (כיוון, לא תסריט)
1. איך מתאמנת חדשה מגיעה אלייך היום, וכמה בחודש?
2. איך המתאמנות מקבלות תפריט ואיך את עוקבת אחריהן?
3. איך את עוקבת אחרי אימונים ושאלונים?
4. מה את משתמשת היום (וואטסאפ, טפסים, אינסטגרם)?
5. אם כל זה היה עובד, מה זה שווה לך בחודש?

## מה אמור לצאת (מפתח תשובות)
הקובץ `fixtures/fitness-golden.json` הוא התיק שהיינו מצפים לו:

| רכיב | שלב |
|---|---|
| עמוד ארוחות לפי מנות | 1 |
| עמוד מעקב אירובי | 1 |
| עמוד טפסים דינאמי | 1 |
| חבר מביא חבר | 1 |
| עמוד התראות ווצאפ (ריטיינר חודשי) | 1 |
| עמוד תוספי תזונה | 2 |

הערכה לפי הקטלוג: ₪5,650 חד-פעמי, ₪150 בחודש, החזר כמעט תוך חודשיים מול 3,000 בחודש.

## איך מריצים
1. מקליטים בדף הלכידה (`npm run capture`) ומורידים את ה-JSON, או מקליטים קובץ ומריצים `npm run transcribe:live`.
2. מריצים את Claude על התמלול:
   ```bash
   npm run simulate -- <תמלול.json> --catalog catalog/fitness-mock.json
   ```
3. משווים לתיק הצפוי:
   ```bash
   npm run score -- --golden fixtures/fitness-golden.json out/<…>/sim/<…>/dossier-v<N>.json
   ```
